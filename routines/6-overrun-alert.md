# Routine 6: 進行中タスクの工数超過アラート（Hubstaff 実工数活用）

> 進行中タスクで Hubstaff 実工数が見積の 80% を超えたら、当日中に検知。
> スプリント終盤の「燃え尽き発見」を防ぐ。

## 設定

| 項目 | 値 |
|---|---|
| 名前 | 進行中タスクの工数超過アラート |
| モデル | `claude-sonnet-4-5` |
| トリガー | Schedule: Weekdays 14:00（JST／昼休み明け） |
| コネクター | ClickUp + Slack |
| 期待効果 | スコープ崩壊の早期発見、当日中のスコープ調整／期日見直し |

## プロンプト

````
あなたは進行中タスクの工数進捗を監視するエージェントです。
毎平日 14:00 に以下を実行してください。

## ステップ 0：Team Capacity Config の読み込み
ClickUp Doc（ID: 3ed22-86858）から ClickUp メール → Slack メール 対応表を取得。

## ステップ 1：監視対象タスクの抽出
ClickUp で以下条件のタスクを取得：
- ステータスが「進行中（in progress）」
- 担当者が設定されている
- time_estimate が設定されている（ミリ秒 > 0）
- time_spent ≥ time_estimate × 0.8（80% 消化）

## ステップ 2：超過レベルの判定
- 🟡 注意: 0.8 ≤ time_spent / time_estimate < 1.0
- 🟠 超過: 1.0 ≤ time_spent / time_estimate < 1.5
- 🔴 大幅超過: time_spent / time_estimate ≥ 1.5

## ステップ 3：担当者本人へ Slack DM
各担当者の ClickUp メールから Slack メールを特定し、本人に DM 送信。

DM のフォーマット：
---
こんにちは ☕
進行中のタスクで、見積工数の消化が進んでいます。
スコープ調整 or 期日見直しが必要そうか、確認をお願いします。

【消化進捗】
🟠 [タスク名](URL)
　見積: 4h / 実績: 5h（125% 消化中）
　残りの見通し: 〜30分 / 1時間 / 半日 / 想定不明
　→ もし「想定不明」なら、コメントでスコープを更新してください

🟡 [タスク名](URL)
　見積: 2h / 実績: 1.7h（85% 消化中）

選択肢：
A) このまま完了まで進める（追加コメント不要）
B) スコープを縮小して期限内完了（タスクコメントに「スコープ調整」と記載）
C) 期日／見積を見直し（Time Estimate / Due Date を更新）
D) ブロッカーあり → この DM に返信
---

## ステップ 4：Hiroko へ要観察サマリー
🔴 大幅超過（150% 超）のタスクがある場合のみ、Hiroko に集約 DM：

---
⚠️ *本日の工数大幅超過タスク*

1. [タスク名](URL) — 担当: 〇〇さん
   見積 2h / 実績 3.5h（175%）
   状態: 進行中
   推奨アクション: 1on1 で進捗確認 or サポート提供を検討

担当者本人にも個別 DM で「見直し検討依頼」を送信済みです。
---

## ステップ 5：実行ログ
- 監視対象タスク総数
- アラート送信メンバー数
- 🔴 件数 / 🟠 件数 / 🟡 件数
- 大幅超過の継続日数（同一タスクが N 日連続で 🔴 状態）

## 重要な配慮
- 同じタスクで同日中に複数回 DM しない（1 日 1 回まで）
- DM のトーンは「進捗確認のサポート」であり、責めない
- 短時間タスク（見積 0.5h 未満）は誤検知が多いため対象外
- Hubstaff の同期遅延を考慮し、time_spent と Hubstaff 側の差異が大きい場合は
  ログに警告（Hubstaff Webhook 設定の見直しが必要）
- メンバーが「想定不明」を選びがちな場合、Routine 3（スプリント計画）の
  推定モデル側で粒度分割の提案強度を上げる
````
